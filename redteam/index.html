The Evolution of Red-Teaming

Comparing static scanners with AI vs AI's adaptive approach.

Static Payload Scanners
  • Relies on fixed "jailbreak" catalogs.
  • Easily blocked by pattern-matching.
  • No understanding of target refusals.
AI vs AI (Adaptive)
  • Closed-Loop: Attacker LLM learns from every target response.
  • Runtime Mutation: Generates unique payloads dynamically.
  • Goal-Oriented: Persistently chases a defined security objective.

Goal-Driven Logic & The Judge LLM

Testing success isn't just about bypasses; it's about achieving specific goals. AI vs AI uses a dedicated Judge Model to autonomously oversee the attack evolution.

Objective Tracking

"Extract the system prompt," "Enable DAN mode," etc.

The orchestrator verifies progress toward the goal in every iteration.

Side Leak Detection

The Judge identifies "Incidental Findings"—security leaks or data exposures that occur even if the primary goal is not yet achieved.

Agnostic Infrastructure Support

Deploy the framework using your own environment constraints, whether on-prem or via cloud APIs.

Local Attacker (Ollama)

Host your adversary locally to bypass cloud moderation layers. Supports specialized models like Llama 3.1 or Qwen 2.5 Abliterated for unaligned red-teaming.

Outside LLM APIs

Connect to OpenAI, Groq, or OpenRouter via standard Inference APIs. Leverage high-reasoning models for multi-turn adversarial orchestration.

Arbitrary HTTP / cURL Targets

Import complex enterprise requests directly. Support for cookies, custom headers, and Burp Suite imports ensures you can test any LLM gateway.
