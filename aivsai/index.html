Why AI vs AI Exists

Many LLM testing workflows still depend on static payload lists and one-shot jailbreak prompts. Modern AI systems behave differently. Guardrails shift. Context matters. Refusals partially weaken. Some attacks create side leaks before direct compromise. AI vs AI was built to explore that adaptive space.

⬡

Closed-loop, not catalog

The attacker dynamically rewrites payloads based on prior failures, partial successes, judge feedback, and behavioral drift.

◎

Goal-aware judge scoring

The judge watches whether the target is getting closer to the attack objective instead of relying on simplistic success/failure logic.

◈

Hybrid attack engine

AI vs AI mixes pure LLM reasoning with deterministic strategy libraries for repeatability and creative exploration.

⌁

Behavioral side-leak analysis

The framework tracks moderation hints, refusal weakening, hidden workflow disclosures, and indirect information leakage.

The Adaptive Attack Evolution Loop

01Attacker LLM

Generates adversarial payloads using the testing goal, historical failures, previous responses, and judge observations.

02Target Application

Processes payloads through real HTTP workflows. Targets can include APIs, RAG systems, or custom AI applications.

03Judge Model

Scores relevance, behavioral drift, prompt leakage, refusal weakening, and extraction progression.

04Orchestrator

Feeds observations back into the attacker to mutate strategies, pivot attack families, and escalate context manipulation.

Pure LLM vs Library vs Hybrid Mode

AI vs AI supports multiple adversarial generation styles to balance repeatability and creativity.

Mode Description
Pure LLM Attacker relies entirely on model reasoning to evolve payloads dynamically.
Library Mode Uses deterministic attack families, reusable mutations, and controlled escalation logic.
Hybrid Mode Combines LLM creativity with repeatable library mutations and scoring-driven pivots.
Judge-driven Evolution Future payloads adapt according to scoring progression instead of binary success/failure.
Behavioral Side Leaks Tracks moderation hints, workflow disclosures, hidden reasoning patterns, and refusal logic exposure.
